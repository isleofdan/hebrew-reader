## What the study tool needs

- **Keys:** walks and stops are keyed by Sefaria's canonical references (`walks.start_ref`, `asks.ref`, `passages.ref`), the form Sefaria's Texts API answers in (`Shabbat 112b`, `Genesis 1:1-3`).
- **Start a walk here:** `/walks?ref=<reference>` (the page) or `POST /walks/start { ref }` (the data route) starts a walk at a passage: the first stop is that passage, with the guide asking what the reader notices. A "start a walk here" press has to send the passage's canonical reference to that address and nothing else.
- **Table of contents:** Sefaria's index interface (`/api/index` for the whole library's tree, `/api/v2/index/<title>` for one book's shape: sections, their lengths and names) gives Tanakh's books and chapters and the Talmud's tractates and pages; Sefaria's calendar interface (`/api/calendars`) gives the day's Daf Yomi and the other reading cycles. Both are read-only GETs with no key, like the Texts API the code already uses, and belong in `lib/sefaria.js` beside `passage(ref)`.
- **A reading position:** a small table of its own beside `walks` (for example `positions(id, ref, updated_at)`, or one row per cycle), not a column on `walks`, since a position exists without a walk.
- **What the walk page lacks for a walk started at a passage:** it shows the passage as the title and no question, which is right, but it has no link back to the place in the table of contents, no "next page" or "previous page" of the text, and no way to continue the sequential study from the walk; those sit in the later step.
- **Interface and address rule the code uses:** Texts API v3 (`GET /api/v3/texts/<ref>?version=hebrew&version=english`), and the sefaria.org address built from the canonical reference by `lib/references.js` (spaces to `_`, `:` to `.`, the space before the sections to `.`).
